## 1순위 비용 예시

포트원 경유 KG이니시스 통합인증의 공개 가격인 성공 건당 40원을 적용한 값이다.

| 월 성공 건수 | 예상 비용 |
|---:|---:|
| 100건 | 4,000원 |
| 1,000건 | 40,000원 |
| 5,000건 | 200,000원 |
| 10,000건 | 400,000원 |

포트원 플랫폼은 월 순거래액 5,000만원 미만 Free 요금제에서 본인인증 연동을 제공한다. 본인인증 원천사 비용은 별도로 발생한다.

다날은 가장 낮은 요금제가 월 5만원에 1,200건을 포함한다. 가입자가 적은 초기에는 사용량과 무관하게 기본료가 발생하므로 KG이니시스 성공 건당 요금이 유리하다.

## 왜 포트원 + KG이니시스인가

1. 성공한 인증에만 건당 비용이 발생해 초기 고정비가 작다.
2. PASS를 포함한 여러 인증 앱을 한 번의 계약과 한 화면으로 제공한다.
3. 계약 전에 테스트 모드로 개발할 수 있다.
4. 현재 프로젝트 Flutter 버전은 공식 `portone_flutter` SDK 요구사항을 충족한다.
5. 포트원의 API로 원천사를 바꿀 수 있어 향후 다날이나 KCP로 교체하기 쉽다.
6. PASS 인증에서는 CI를 받을 수 있어 실제 명의 확인과 1인 1계정 판정에 사용할 수 있다.

## 확인해야 할 제약

- KG이니시스 통합인증은 DI를 제공하지 않는다. 올라운드가 1인 1계정 확인만 필요하다면 CI로 처리할 수 있다.
- 카카오 인증은 CI 제공에 별도 서류가 필요하므로 1차 출시에서는 PASS를 기본 수단으로 두고 카카오는 제외하거나 계약을 보완한다.
- 내·외국인, 통신사, 성별은 KG이니시스 통합인증 기본 응답에 포함되지 않는다. 대회 자격 판단에 반드시 필요하면 계약 전에 별도 확인한다.
- 본인확인 서비스는 결제와 별도로 단독 이용할 수 있지만 PG사 계약은 필수다.
- KG이니시스 공식 안내상 인증사 심사와 계정 발급에 최대 1~2주가 걸릴 수 있다.
- 공개 가격은 변경될 수 있으므로 신청 직전에 포트원에서 서면 견적을 다시 받는다.

## 권장 시스템 흐름

```text
Flutter 앱
  → PortOne Flutter SDK에서 PASS 본인확인
  → 앱은 identityVerificationId만 Supabase Edge Function에 전달
  → Edge Function이 PortOne API로 VERIFIED 상태와 결과를 재조회
  → 서버가 현재 로그인한 Supabase 사용자에게 인증 결과를 연결
  → DB에는 인증 시각·제공자와 중복 확인용 CI 가명값만 최소 저장
```

- 클라이언트가 전달한 이름·생년월일·성공 여부를 신뢰하지 않는다.
- PortOne API Secret은 Edge Function secret으로만 보관한다.
- CI 원문은 로그, 오류 메시지, 분석 SDK, Crashlytics에 남기지 않는다.
- 중복 확인용 CI 가명값도 재연결 가능한 개인정보로 취급하고 RLS 및 관리자 접근을 제한한다.
- 가입 전체에 즉시 강제하기보다 대회 신청·클럽장 등록 등 신뢰가 필요한 최초 시점에 한 번 인증하는 방식을 우선 검토한다.

## 개인정보 출시 조건

현재 처리방침에는 포트원·KG이니시스, 휴대전화번호, CI 기반 식별값, 본인확인 처리 흐름이 기재되어 있지 않다. 실제 도입 전에는 아래가 필요하다.

1. 개인정보 처리방침에 수집 항목·목적·보유기간과 수탁자 추가
2. 본인확인 화면에서 필요한 고지·동의 문구와 만 14세 미만 흐름 확정
3. Apple App Privacy와 Google Play Data Safety 선언 갱신
4. 탈퇴 시 DB 가명값과 공급자 측 보관 데이터의 처리 방식 확정
5. 운영 로그·Crashlytics·고객지원 화면에 CI·전화번호가 노출되지 않는지 테스트

도입 전 개인정보 판정은 현재 `VERIFY`다. 계약, 데이터 항목, 보관기간, 처리방침을 확정하기 전에는 운영 출시하지 않는다.
