# 올라운드 자체 작업 시연 Runbook — 2026-08-20 목요일

> 실제 앱을 직접 보여주는 내부 시연 기준. 영상·스크린샷 백업은 만들지 않는다.
> 본편 6분 15초, 지연 흡수 45초를 포함해 총 7분으로 운영한다.

## 발표의 임무

> 시연이 끝났을 때 청중이 올라운드를 ‘개발 중인 기능 모음’이 아니라 ‘광주·전남 동호인의 반복적인 수고를 줄이는 출시 제품’으로 이해하고, 2주 파일럿 진행에 동의하게 만든다.

청중이 기억해야 할 문장:

> **대회 찾는 시간은 줄이고, 같이 뛰는 시간은 늘립니다.**

발표에서 반복할 세 가지 약속:

1. **내 등급에 맞는 대회가 먼저 보입니다.**
2. **애매한 참가 조건과 마감 기억을 줄여줍니다.**
3. **개인의 대회 탐색을 클럽 활동으로 이어줍니다.**

기능 목록이 아니라 다음 인과관계로 말한다.

> 정보가 없는 것이 문제가 아니다 → 정보가 흩어져 행동으로 이어지지 않는다 → 올라운드는 발견·판단·기억·클럽 활동을 연결한다 → 이제 필요한 것은 기능 추가가 아니라 반복 사용 검증이다.

## 발표 시간 배분

| 내용 | 시간 | 원칙 |
|---|---:|---|
| 문제와 제품 약속 | 50초 | 슬라이드 2장, 한 주장씩 |
| 실제 앱 시연 | 4분 | 대회 1개·AI 질문 1개·클럽 1개만 |
| 출시 증거 | 35초 | App Store와 Android 준비 상태를 사실대로 |
| 다음 검증과 요청 | 50초 | 2주 파일럿 결정을 요청 |
| 지연 흡수 | 45초 | 남으면 바로 Q&A로 전환 |

프레젠테이션은 네 장만 사용한다. 기술 아키텍처, 기능 목록, 전체 로드맵은 본편에 넣지 않는다.

## 프레젠테이션 4장

### 1장 — 대회 하나를 찾기 위해 왜 네 군데를 확인해야 할까요?

화면에는 네 단어만 크게 둔다.

> 협회 홈페이지 → 요강 → 단톡방 → 개인 일정

발표 문장:

> 이번 주말 나갈 대회가 있는지 확인하려면 협회 홈페이지에서 일정을 찾고, 요강에서 참가 부서를 확인하고, 단톡방에 다시 물어보고, 마감일까지 기억해야 합니다. 문제는 정보가 없는 것이 아니라, 정보가 흩어져 다음 행동으로 이어지지 않는다는 것입니다.

“오늘 개발한 기능을 보여드리겠습니다”라고 시작하지 않는다.

### 2장 — 올라운드는 흩어진 정보를 다음 행동으로 바꿉니다

보조 문구:

> 내 등급 대회 → 조건 확인 → 마감 기억 → 클럽 활동

발표 문장:

> 지금부터 광주협회 골드부 동호인이 자신에게 맞는 대회를 발견하고 클럽 활동까지 이어가는 과정을 보여드리겠습니다.

이 문장 뒤 슬라이드를 내리고 앱만 보여준다.

### 3장 — 이제 아이디어가 아니라 사용을 검증할 제품입니다

화면에는 세 가지 사실만 둔다.

- iPhone 앱 App Store 출시
- 실제 대회·규정 데이터와 출처를 사용하는 볼보이
- Android API 36 빌드 검증 완료

발표 문장:

> iPhone 앱은 실제 출시됐습니다. Android도 API 36 기준 코드와 빌드 검증을 마쳤고, 최종 업로드 키 서명과 Android 16 기기 검증, 회사 계정 절차가 남았습니다. 방금 본 흐름은 콘셉트가 아니라 실제 앱에서 동작합니다.

`AAB`, `RAG`, `SSE`, `Supabase`, `pgvector`는 질문이 나오기 전까지 말하지 않는다. API 36도 실행력의 증거로만 10초 이내에 설명한다.

### 4장 — 다음 2주는 기능 추가가 아니라 반복 사용을 확인합니다

검증 목표:

- 광주·전남 클럽 5곳
- 실제 사용자 100명
- 사용자당 관심 대회 평균 2개
- 7일 재방문율 40%

오늘 요청할 결정:

1. 2주 파일럿 진행 승인
2. 시범 클럽 5곳 연결 담당자 지정
3. 파일럿 기간에는 새 기능보다 데이터 정확도·알림·온보딩을 우선한다는 합의
4. Google Play 회사 계정·D-U-N-S·업로드 키 담당자와 완료 목표일 확정

클로징 문장:

> **올라운드가 증명한 것은 ‘만들 수 있다’는 것입니다. 이제 증명할 것은 ‘지역 동호인이 반복해서 쓴다’는 것입니다.**

## 6분 15초 Run-of-show

### 0:00–0:25 — 문제 제시

- 1장을 보여준다.
- 문제 문장을 말한다.
- 앱과 기술을 아직 언급하지 않는다.

### 0:25–0:50 — 제품 약속

- 2장을 보여준다.
- 광주협회 골드부 사용자라는 상황을 선언한다.
- “이제 실제 앱에서 보겠습니다”라고 말한 뒤 앱으로 전환한다.

### 0:50–1:25 — 홈에서 내 대회가 먼저 보인다

시작 상태:

- 로그인 완료
- 활성 종목 `테니스`
- 지역 `광주`
- 광주협회·골드부 등록 완료
- 홈 첫 영역에 고정 대회 노출

조작:

1. 홈을 2초간 그대로 보여준다.
2. 시연 대상 대회 카드 하나만 짚는다.
3. 검색과 필터를 만지지 않고 `대회 보기`로 상세를 연다.

발표 문장:

> 종목과 협회, 등급은 한 번만 등록합니다. 이후에는 조건을 매번 다시 입력하지 않아도 자신이 확인할 대회부터 정리됩니다.

홈 화면에서는 카드 디자인이 아니라 **나와 상관없는 정보를 덜어냈다**는 점만 강조한다.

### 1:25–2:15 — 상세에서 판단 비용을 줄인다

조작:

1. 일정과 장소를 짚는다.
2. 참가 부서와 참가비를 짚는다.
3. `대회 요강`을 펼친다.
4. 원문 링크는 열지 않고 연결돼 있다는 것만 보여준다.
5. 아직 저장되지 않은 관심 버튼을 한 번 누른다.

발표 문장:

> 형식이 제각각인 공고를 일정, 장소, 참가 부서, 참가비라는 같은 구조로 확인합니다. 중요한 결정은 원문 공고에서 다시 확인할 수 있습니다. 관심 대회로 저장하면 신청 마감과 대회 일정을 다시 알려주기 때문에 사용자가 계속 기억할 일도 줄어듭니다.

관심 목록과 알림함은 별도로 열지 않는다. 저장 동작 하나로 설명을 끝낸다.

### 2:15–3:15 — 현재 대회를 이해하는 볼보이

조작:

1. 대회 상세를 유지한 채 하단 `볼보이`를 연다.
2. `현재 대회 연결`을 켠다.
3. 미리 검증한 질문 하나만 입력한다.

라이브 질문:

> 골드부 참가 가능해?

응답 뒤 출처 또는 대회 카드를 짚는다.

발표 문장:

> 요강을 읽어도 애매한 부분은 화면을 떠나지 않고 묻습니다. 현재 대회 연결은 인터넷 전체를 추측하게 하는 것이 아니라, 지금 보고 있는 공개 대회 정보를 질문에 함께 쓰겠다는 뜻입니다. AI가 참가 결정을 대신하지는 않습니다. 확인 시간을 줄이고 중요한 내용은 출처에서 다시 검증하게 합니다.

첫 질문이 성공하면 후속 질문을 하지 않고 즉시 다음 장면으로 이동한다.

### 3:15–4:30 — 클럽 활동으로 이어진다

조작:

1. 볼보이 시트를 닫는다.
2. 하단 `클럽`을 누른다.
3. 한 번만 스크롤해 `나의 클럽`의 고정 카드를 연다.
4. `모임` 탭을 연다.
5. 미래 일정 하나와 참석 현황을 보여준다.
6. 데이터 상태가 확실할 때만 `응답자 보기`를 연다. 참석 상태는 바꾸지 않는다.

발표 문장:

> 대회는 개인이 찾지만 실제 운동은 클럽에서 이어집니다. 올라운드에서는 참여 중인 클럽의 다음 모임과 참석 현황을 같은 흐름에서 확인합니다. 핵심은 대회, AI, 클럽 기능이 각각 있다는 것이 아니라 발견한 정보가 판단과 기억을 거쳐 실제 클럽 활동까지 끊기지 않는다는 것입니다.

모집글, 게시판, 회비와 멤버 권한은 열지 않는다.

### 4:30–5:05 — 출시 증거

- 앱에서 3장으로 전환한다.
- App Store 출시와 Android의 정확한 준비 상태만 설명한다.
- Android를 “출시 완료” 또는 “계정 인증만 남음”이라고 말하지 않는다.

### 5:05–6:15 — 다음 결정 요청

- 4장을 보여준다.
- 목표 수치는 현재 성과가 아니라 앞으로 검증할 기준이라고 말한다.
- “피드백 부탁드립니다”로 끝내지 않고 네 가지 결정을 요청한다.
- 클로징 문장을 말한 뒤 멈춘다.

### 6:15–7:00 — 지연 흡수 또는 Q&A

- 본편이 밀리면 이 시간을 사용한다.
- 제시간에 끝나면 즉시 질문을 받는다.
- 시간이 남았다는 이유로 다른 기능을 추가 시연하지 않는다.

## 시연 기기와 앱 빌드

현재 개발 환경에서 확인된 기기:

- iPhone: iOS 26.6
- Android: LM Q510N, Android 9

권장 구성:

1. 최신 성능의 iPhone을 주기기로 사용한다.
2. 발표 당일에는 무선이 아니라 케이블로 연결한다.
3. macOS QuickTime의 iPhone 화면 입력으로 투사한다.
4. 최신 코드가 필요하면 동일한 확정 커밋의 profile 빌드를 사용한다.
5. App Store 버전을 쓸 경우 개발본의 기능을 섞어 설명하지 않는다.

| 선택 | 장점 | 주의점 | 권장 상황 |
|---|---|---|---|
| App Store 1.0.0 (5) | 출시 증거와 안정성이 명확 | 최신 작업이 포함되지 않을 수 있음 | 출시 제품 시연 중심 |
| 확정 커밋 profile 빌드 | 최신 흐름과 성능을 보여줌 | 서명·백엔드 버전 일치 확인 필요 | 최신 작업 시연 중심 |
| debug 빌드 | 설치와 로그 확인이 쉬움 | 성능 저하와 개발 흔적 가능 | 리허설 전용 |

현재 작업공간에는 여러 미커밋 변경이 함께 있다. 발표용 빌드는 반드시 **어떤 커밋과 변경을 사용했는지 기록한 뒤** 만든다. 목요일 아침의 우연한 최신 상태로 빌드하지 않는다.

시연 계정에는 실제 개인 이름, 개인 채팅, 사적인 알림을 남기지 않는다.

## 목요일 시작 상태

홈의 지역 선택은 앱을 다시 열면 `전국`으로 초기화되고 볼보이 대화는 메모리에만 남는다. 따라서 T-30분 확인 후 앱을 완전히 종료하지 않는다.

1. 고정 대회에서 AI 준비 질문을 한 번 성공시켜 실제 앱 안에 답변을 남긴다.
2. 볼보이 미니 바를 닫아 숨긴다.
3. 관심 상태를 미저장으로 돌린다.
4. 클럽 모임과 응답자 표시를 확인한다.
5. 홈으로 돌아와 `테니스`, `광주`, 화면 맨 위를 맞춘다.
6. 앱을 종료하지 않고 그대로 둔다.

AI 상태가 Yellow이면 새 질문을 보내지 않고 준비 답변과 출처만 보여준다. 이것은 녹화나 캡처가 아니라 같은 실기기 안의 실제 앱 상태다.

## 발표 운영 원칙

### 말과 조작을 분리한다

매 장면에서 같은 순서를 지킨다.

1. 다음에 무엇을 확인할지 한 문장으로 말한다.
2. 말을 멈추고 조작한다.
3. 화면이 안정되면 손을 멈춘다.
4. 결과의 의미를 한 문장으로 말한다.

타이핑, 스크롤과 로딩 중에는 설명하지 않는다. 클럽 화면의 스크롤은 한 번만 허용한다.

### 화면마다 한 가지만 증명한다

- 홈: 개인화
- 대회 상세: 판단 비용 감소와 관심 저장
- 볼보이: 현재 맥락을 이용한 확인 시간 단축
- 클럽: 실제 활동으로 연결

### 5초 규칙

어떤 장면이든 5초 이상 멈추면 원인을 설명하거나 현장에서 디버깅하지 않는다.

- 한 번만 기다린다.
- 한 문장으로 상황을 인정한다.
- 해당 장면을 삭제하고 다음 가치로 이동한다.

공통 복구 문장:

> 이 장면은 여기서 기다리지 않고 건너뛰겠습니다. 핵심은 사용자가 별도 채널로 이동하지 않고 현재 흐름에서 다음 판단을 이어간다는 점입니다.

## 영상·스크린샷 없는 상황별 복구

| 상황 | 행동 | 말할 문장 |
|---|---|---|
| 홈이 비거나 지연 | 3초 후 대회 목록 또는 클럽으로 이동 | “개인화 목록 연결은 건너뛰고 실제 활동 흐름을 보겠습니다.” |
| 대회 상세 지연 | 재시도하지 않고 클럽으로 이동 | “상세 응답은 기다리지 않고 다음 반복 사용 흐름으로 넘어가겠습니다.” |
| 관심 저장 실패 | 재시도 없이 볼보이로 이동 | “관심 저장은 마감 알림으로 이어지는 행동입니다. 다음 흐름으로 이동하겠습니다.” |
| AI 첫 응답 지연 | 6초 후 응답 중지, 시트 닫기 | “실시간 응답은 네트워크 영향을 받아 건너뛰고 클럽 흐름으로 넘어가겠습니다.” |
| 클럽 지연 | 재시도 없이 3장으로 이동 | “클럽에서는 다음 모임과 참석 현황을 같은 계정에서 관리합니다.” |
| 앱 종료 | 한 번만 재실행 | “라이브 시연이라 앱을 한 번 다시 열겠습니다.” |
| 로그인 만료 | 재로그인하지 않고 3장으로 이동 | “핵심 사용자 흐름은 여기까지 확인하고 현재 출시 상태를 말씀드리겠습니다.” |
| 미러링 끊김 | 케이블 재연결 한 번, 20초 제한 | “화면 연결을 한 번만 다시 잡고, 복구되지 않으면 결론으로 이동하겠습니다.” |

내부 시연이므로 오류를 숨길 필요는 없지만 원인 분석은 시연 후에 한다.

## 예상 질문과 20초 답변

### 정확히 누구를 위한 앱인가?

첫 고객은 광주·전남 테니스 동호인과 클럽 운영진이다. 지역과 등급이라는 구체적인 문제부터 해결한 뒤 확장한다.

### 기존 테니스 앱과 무엇이 다른가?

수도권 매칭·예약보다 광주·전남 협회 대회와 사용자 등급 연결에 집중한다. 대회 탐색이 관심 알림과 클럽 운영으로 이어지는 것도 차이다.

### 협회 홈페이지나 단톡방을 보면 되지 않나?

볼 수는 있지만 형식이 다르고 참가 가능 여부와 마감일을 사용자가 매번 다시 판단해야 한다. 올라운드는 그 반복 작업을 줄인다.

### AI가 틀리면 어떻게 하나?

AI 답변만 믿게 하지 않는다. 등록된 대회·규정 데이터를 바탕으로 답하고 출처를 연결해 중요한 조건은 원문에서 확인하게 한다.

### 데이터가 항상 정확하고 최신인가?

모든 정보의 완전성을 보장한다고 말하지 않는다. 협회 데이터를 수집·구조화하고 출처 확인, 사용자 제보와 운영 검수로 품질을 높인다.

### 지금 실제 출시된 상태인가?

iPhone 앱은 App Store에 출시됐다. Android는 API 36 빌드 검증까지 끝났고 최종 서명, Android 16 기기 검증과 회사 계정 절차가 남았다.

### Android는 언제 출시할 수 있나?

조직 인증 일정은 외부 변수라 날짜를 단정하지 않는다. 계정 활성화와 업로드 키 확보 후 내부 테스트부터 진행한다.

### 풋살도 테니스만큼 완성됐나?

종목 전환과 기본 구조는 준비됐지만 현재 데이터 깊이는 테니스가 앞선다. 풋살은 데이터 소스를 확보하며 단계적으로 확장한다.

### 사용자가 실제로 쓸지는 검증됐나?

출시는 검증했지만 반복 사용은 이제 검증할 단계다. 클럽 5곳과 사용자 100명 파일럿으로 관심 대회 저장과 7일 재방문을 확인한다.

### 다음에 무엇을 더 만들 계획인가?

먼저 새 기능보다 사용을 검증한다. 실제로 대회를 저장하고 다시 들어오는지 확인한 뒤 매칭·예약·수익화를 결정한다.
