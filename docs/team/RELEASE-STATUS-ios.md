## 1. 코드에서 확인된 사실

드론이 저장소를 직접 대조한 결과다. 근거를 함께 적었으므로 재확인할 수 있다.

| 항목 | 값 | 근거 |
|---|---|---|
| 버전 정본 | `version: 1.0.0+5` | `app/pubspec.yaml` |
| 표시 버전 | `1.0.0` | iOS `MARKETING_VERSION`, Android `versionName` 이 pubspec 에서 받아감 |
| 빌드 번호 | `5` | iOS `CURRENT_PROJECT_VERSION = $(FLUTTER_BUILD_NUMBER)` |
| 빌드 5 커밋 | `7b1fc40` (2026-08-03) | `chore(ios): bump release build to 5` |
| iOS 번들 ID | `kr.jyoung.allround` | `Runner.xcodeproj/project.pbxproj` |
| Android 패키지 | `kr.allround.app` | `android/app/build.gradle.kts` |
| Firebase 등록 | iOS·Android 각각 위 ID 와 **일치** | `GoogleService-Info.plist`, `google-services.json` |

**번들 ID 가 플랫폼마다 다르다.** 각자 Firebase 등록과는 맞아서 지금 문제는 아니지만,
딥링크·OAuth 리다이렉트·유니버설 링크를 만질 때 둘을 혼동하면 조용히 깨진다.

### 빌드 5 에 **들어간** 것 / **안 들어간** 것

빌드 5 이후 `main` 에 머지된 것은 출시본에 **없다.**

- 없음: `#377` 랭킹 RPC 권한 회수 · `#380`(#379) 함수 실행 권한 회수 · `#382` 개인 기록장 1단계
- 있음: **협회 랭킹 화면**(`#370`, `b2afedb`) — 빌드 5 시점에 파일 존재 확인

세 개 모두 **서버 쪽 변경**이라 앱 바이너리와 무관하다. 앱이 부르는 RPC 16개와 대조한 결과
회수 대상과 겹치는 것이 **없다**(2026-08-04 확인).

```bash
# 앱이 부르는 RPC 목록 뽑는 법 — 서버 파괴적 변경 전에 항상 이걸로 대조한다
grep -rhoE "rpc\('[a-z_]+'" app/lib | sort -u
```

### 구글 로그인이 iOS 에 없는 이유 — 의도된 것이다

`app/lib/screens/auth/login_screen.dart:501-506`

```dart
// App Store 첫 출시는 자체 이메일 인증만 제공한다. iOS에서 Google 같은
// 제3자 로그인을 노출하면 App Review Guideline 4.8에 따라 동등한
// Sign in with Apple 옵션이 필요하다.
final showGoogleLogin = kIsWeb || defaultTargetPlatform != TargetPlatform.iOS;
```

- **버그가 아니다.** iOS 에서만 버튼을 숨긴 것이고 코드는 그대로 있다.
- **Android·웹에서는 구글 로그인이 정상 동작한다.**
- iOS 에 되살리려면 **Sign in with Apple 구현이 선행 조건**이다. 그것 없이 켜면 다음 심사에서 막힌다.

## 2. 버전 올리는 법

`app/pubspec.yaml` 의 `version:` **한 줄만** 고친다.
`project.pbxproj` 나 `build.gradle.kts` 를 직접 고치지 않는다 — 거기서 pubspec 값을 받아간다.

| 상황 | 예 |
|---|---|
| 리젝 후 재제출, 같은 표시버전 | `1.0.0+5` → `1.0.0+6` |
| 기능 변경을 사용자에게 알림 | `1.0.0+5` → `1.0.1+6` |

**빌드 번호는 증가만 한다.** App Store·Play 모두 한 번 업로드된 번호는 재사용할 수 없다.

## 4. 답에 따라 갈리는 것

**§3-1 이 "정식 출시"라면** 아래가 즉시 처리 대상이 된다. "제출/심사 중"이면 다음 빌드에 담으면 된다.

### 🔴 4-1. 랭킹 화면이 이미 나갔다 — "공개 전 결정"이 미결인 채로

**협회 랭킹 화면은 빌드 5 에 포함돼 있다**(위 §1 확인). 그런데 이 화면을 공개하기 전에
정하기로 했던 항목들이 아직 남아 있다.

가장 급한 것: **`rankings_screen.dart:120` 에 개인 Gmail 이 하드코딩돼 화면에 표시된다.**

```dart
const _kPrivacyContactEmail = 'demian.772@gmail.com';
```

- 이 화면은 **앱 미가입자의 실명을 그대로 표시**한다(선행 설계 §3 결정 4).
- 미가입자에게는 **이 이메일이 삭제를 요청할 유일한 경로**다
  (`docs/team/RUNBOOK-org-ranking-deletion-request.md:9-12`).
- 즉 **Commander 개인 메일 주소가 출시된 앱에 상시 노출**되고, 그 주소로 개인정보 삭제 요청이 온다.

→ 서비스용 주소로 바꾸는 것이 원래 계획이었다. 출시됐다면 **다음 빌드에서 반드시** 교체한다.
→ 처리방침(`legal/privacy-policy.html`)의 연락처도 같이 바꿔야 앱과 어긋나지 않는다.

### 🟠 4-2. 강제 업데이트 장치가 없다

`app/lib` 에 최소 버전 검사·업데이트 유도 코드가 **없다**(2026-08-04 확인).

출시본이 존재하는 지금, 서버를 바꿔 구버전이 깨지면 **사용자를 새 버전으로 밀 방법이 없다.**
되돌리는 것 외에 대응 수단이 없다는 뜻이다.

→ 당장 막는 것은 아니지만, 서버 스키마를 계속 바꿀 계획이라면 이 장치를 넣는 편이 안전하다.

### 🟡 4-3. 체크리스트 미완 항목

`docs/team/store-submission-checklist.md` 기준으로 아직 `[ ]` 인 것 중 심사에 직결되는 것:

- **회원 탈퇴 인앱 동작 E2E 검증** — 코드는 있으나 실기기 검증 대기. Apple 필수 항목이다
- **UGC 안전장치** — DB 마이그레이션·함수 배포 + 실기기 검증 대기
- **AI 생성 콘텐츠 고지** — 실기기 검증 대기

→ 심사를 통과했다면 애플이 이것들을 문제 삼지 않았다는 뜻이다. 다만 **다음 심사에서 걸릴 수 있고**,
정책 위반은 사후에도 지적된다. 실제 동작 여부는 확인해 두는 편이 낫다.

## 5. 서버를 바꿀 때 지킬 것 (출시 이후 새로 생긴 제약)

출시본은 **고정된 바이너리**다. 서버가 계속 그 빌드와 호환돼야 한다.

1. **RPC 시그니처를 바꾸거나 권한을 회수하기 전에** 앱이 그걸 쓰는지 대조한다(§1 의 grep).
2. **테이블·컬럼을 지우기 전에** `app/lib` 의 `.from('...')` 사용처를 대조한다.
3. RLS 정책을 좁힐 때는 **인증 사용자 동작이 그대로인지** 확인한다. anon 만 바뀌는 건 대체로 안전하다.
4. 배포 후 **Supabase advisor** 를 본다. 로컬 초록불이 프로덕션 권한을 보증하지 않는다.
